What the variance actually is

The bot rewrites; our checks can't see it

17 / 21flaky cases where every check stayed the same and the verdict still moved
4 / 21cases where the checks themselves flipped

We first called this “judge noise”. Wrong — the verdict is cached per answer text, so the text must have changed. What we measured is that our checks are blind to how the answers differ.

And it cuts both ways: a check for the literal string “no order” failed a correct “I can't find an order” — three times out of three. There the judge was right and the check was brittle.

What we changed because of it

Stop asking the judge for things a check can prove

1judge self-consistency — same answer, repeated calls, the verdict must hold
2claim extraction — judge lists unsupported claims, code decides pass or fail
3policy facts as checks — services we don't offer, refund promises, PII

“Our live chat is open” then fails because it isn't in the facts, not because a judge happened to feel strict that run.

What we claim, and what we don't

Numbers with their error bars

8/8after re-labelling — that's anchoring, not accuracy

Not claiming: that the judge is N% accurate, that the fix improved quality, or that temperature 0 means deterministic.
The one defensible improvement is latency — one run, shared cloud inference.
